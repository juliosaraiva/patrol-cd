Intermittent `pnpm -C ui test` failure: every test passed, but the run ended with
`Errors  1 error` and `ELIFECYCLE Test failed` (exit 1).

## Reproduction

| Command | Runs | Runs with the error |
|---------|------|---------------------|
| `pnpm -C ui test` (no extra load) | 1 | 1 |
| `npx vitest run src/main.test.tsx` (no extra load) | 6 | 1 (run 5) |
| same, with a temporary fetch-tracing setup file (removed afterwards) | 9 | 1 (run 9) |
| `pnpm -C ui test` × 12 under load (pre-fix) | 12 | 1 (run 11, same stack, same file) |

The tracing setup logged MSW `request:start` events and wrapped the fetch MSW delegates to. In
**all 9** traced runs, `GET http://localhost:3000/api/v1/stream/applications?resourceVersion=100`
went to that underlying fetch about 25 ms **after** `afterAll` closed the MSW server, so the
request left the process. In the failing run, the answer came back as `401` (from the Grafana
container on port 3000) and the error followed. In the other runs the worker exited before the
answer arrived.

The 12 pre-fix runs under load also showed two unrelated load-sensitive test failures (not
unhandled errors; see "Other load flakes"): run 7 (`contract.test.ts` timeout) and run 9
(`contract.test.ts` timeout + `shell.test.tsx` shortcuts dialog).

## Root cause

`src/main.test.tsx` runs the real bootstrap (`import('./main')`). `main.tsx` mounts the app with
its own `createRoot`, which Testing Library's `cleanup()` does not know about, so **the app was
never unmounted**. After the test:

1. The application list loads, and `useApplications` opens the watch stream
   `/api/v1/stream/applications`. This often happens after the test body has finished, and after
   `afterAll` has called `server.close()`.
2. With MSW closed, `fetch` is Node's real fetch, and the URL resolves against jsdom's origin
   `http://localhost:3000`. On this host a Grafana container listens there and answers `401`.
3. `openStream` treats 401 as an expired session and calls `notifyUnauthorized()`, which reads
   `window.location`. If jsdom has already been torn down, this throws `ReferenceError: window is
   not defined` inside a promise chain, and vitest reports it as an unhandled rejection.

The leak is deterministic; the symptom is a race between the 401 arriving and the worker
exiting, which is why it was intermittent. Without a service on port 3000 the request fails with
`ECONNREFUSED`, which the stream handles silently, so the leak was invisible on other hosts.
The application code (`openStream`, `useListWatch`, `useApplication`) already closes streams on
unmount; the defect was the test leaving the app mounted.

## Fixes

1. **Stop the bootstrapped app** — `ui/src/main.tsx` exports `started: Promise<StartedApp>`;
   `stop()` unmounts the root, disposes the router and clears the query cache.
   `ui/src/main.test.tsx` stops the app (and removes `#root`) in `afterEach`. The test now also
   waits for the watch stream to open, stops the app, and asserts the root is empty and every
   `/api/v1/stream/*` request it made is aborted. A sanity run with the in-test `stop()` removed
   failed on `toBeEmptyDOMElement()`.
2. **Guards** (`ui/src/test/guards.ts`, wired in `ui/src/test/setup.ts`). These fail the
   offending test with `[test-guard] "<describe > test>" in <file>: ...`:
   - unmocked requests. The `onUnhandledRequest` callback records the request and throws. In MSW
     2.15, a custom callback's `print.error()` only logs and the request **passes through to the
     network**; a thrown error makes MSW fail the request as the `'error'` strategy does;
   - unhandled rejections and uncaught exceptions (`process` listeners for the file's lifetime);
   - `console.error` output, except the allow-list `ALLOWED_CONSOLE_ERRORS`. Each entry names a
     file, a test and a message pattern; the list covers the three intentional error-boundary
     tests (`shell.test.tsx` "shows recovery guidance when the server is unreachable",
     `errors.test.tsx` "offers sign-in for expired sessions" and "shows technical details and a
     reload action for unexpected errors"). The guard does not swallow output: the original
     `console.error` still prints;
   - elements left in `document.body` after `cleanup()`, which means UI was mounted outside
     `render`/`renderApp` and keeps running;
   - real network: `blockRealNetwork()` replaces the fetch MSW wraps (installed before
     `server.listen()`), so a request made outside MSW's lifetime rejects with a `[test-guard]
     blocked a real network request` error and a stderr line, and never reaches a local service.
   Findings made while no test runs fail the file in `afterAll`.
3. **Other load flakes** found during the stress runs (separate from the unhandled error):
   - `ui/src/api/contract.test.ts` "answers every called operation from the default mocks with
     documented shapes" is one sequential, CPU-bound sweep over every client case. It takes 3.4 s
     idle and 6.3–10.8 s under load, so it hit the 10 s default timeout in pre-fix runs 7 and 9.
     It now has `{ timeout: 60_000 }`.
   - `ui/src/shell/shell.test.tsx` "supports the skip link and the / and ? shortcuts" (pre-fix
     run 9: the dialog was still open after Escape). Cause in the app: `useRouteChangeFocus` (in
     `ui/src/shell/AppShell.tsx`) moved focus to `<main>` whenever the path changed, including
     when a route committed while a modal dialog was open. That took focus out of the dialog's
     focus trap, so Escape never reached it. The test's `waitFor` resolves on
     `router.state.location` before React commits the route (a transition), so under load the
     commit could land after `?` opened the dialog. A probe test with an explicit
     `router.navigate()` while the dialog was open reproduced it deterministically (focus on
     `MAIN`, dialog still open after Escape). The fix leaves focus alone when it is inside an
     `aria-modal` dialog (the title is still announced). New test: "leaves focus in a dialog that
     stays open while a route change commits". It fails without the fix and passes with it.

## Guard verification

A temporary test file (deleted afterwards) with one case per guard, run with
`npx vitest run src/zz-guard-probe.tmp.test.tsx`: 5 of 5 offending tests failed with the
expected `[test-guard]` message (unmocked request, `console.error`, allow-listed text in a
non-allow-listed test, unhandled rejection, root mounted outside `render()`), and the clean
control test passed.

The pre-fix `main.test.tsx` was run as a temporary file under the guards
(`npx vitest run src/zz-old-main.tmp.test.tsx`, 5 runs). It failed **5 of 5** with
`DOM left mounted after cleanup(): <div id="root"> still in document.body ...`. Each run printed
`[test-guard] blocked a real network request: GET
http://localhost:3000/api/v1/stream/applications?resourceVersion=100 ...` and reported 0
unhandled errors. The leak is now a deterministic, named test failure instead of a
host-dependent run error.
